# Quest 3 Performance Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise race smoothness toward a stable 72 FPS / 13.89 ms frame budget on Quest 3 without reducing any visual quality.

**Architecture:** Keep the current rendering output unchanged and remove only wasted CPU/GPU work. First activate the already-generated VR-aware course culling source, then optimize hot native code generation and remove runtime diagnostics/synchronizations that do not contribute to visible output. Each change is verified independently by inspecting the actual generated Ninja graph and by rebuilding the APK.

**Tech Stack:** Android NDK 27, CMake, Gradle 8.5, C/C++20, OpenXR 1.1, OpenGL ES 3.2, libultraship/Fast3D.

## Global Constraints

- Quest 3 target refresh remains 72 Hz.
- Current eye render resolution and `kWorldRenderScale` remain unchanged.
- No textures, geometry, skybox, fog, HUD, draw distance, effects, or FFR quality may be reduced.
- No change to 6DoF behavior, diorama mode, controller mapping, audio, GP flow, or race marker rendering.
- Every optimization must preserve buildability and current visual output.

### Task 1: Compile the VR-aware course culling source

**Files:**
- Modify: `app/src/main/cpp/cmake/GDiffuserGame.cmake`
- Generated/verify: `app/.cxx/Debug/*/arm64-v8a/build.ninja`

**Interfaces:**
- Consumes: `GDX_QUEST_COURSE` generated by `GDiffuserQuestPatches.cmake`.
- Produces: `gdiffuser_game` built from `course_quest.c` instead of upstream `src/game/course.c`.

- [ ] **Step 1: Verify the current build graph is wrong**

Run:
```bash
rg -n "course(_quest)?\\.c\\.o" app/.cxx/Debug/*/arm64-v8a/build.ninja
```
Expected before fix: `src/game/course.c.o` is present and `gdx_quest_generated/course_quest.c.o` is absent.

- [ ] **Step 2: Implement the minimal CMake source substitution**

In `GDiffuserGame.cmake`, exclude `/game/course.c$` from `GDX_GAME_SOURCES` and add `${GDX_QUEST_COURSE}` to the `gdiffuser_game` source list. Do not change any culling constants or rendering quality settings.

- [ ] **Step 3: Reconfigure/build**

Run:
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-quest.ps1 -Configuration Debug
```
Expected: `BUILD SUCCESSFUL`.

- [ ] **Step 4: Verify the actual compiled graph**

Run:
```bash
rg -n "course(_quest)?\\.c\\.o" app/.cxx/Debug/*/arm64-v8a/build.ninja
```
Expected after fix: `gdx_quest_generated/course_quest.c.o` is present and upstream `src/game/course.c.o` is absent.

### Task 2: Raise hot native compilation from O2 to O3

**Files:**
- Modify: `app/src/main/cpp/CMakeLists.txt`
- Modify: `app/src/main/cpp/cmake/GDiffuserGame.cmake`

**Interfaces:**
- Consumes: existing alias/wrap safety flags.
- Produces: same native ABI and output, compiled with stronger optimization for CPU-heavy Quest paths.

- [ ] **Step 1: Verify current flags**

Run:
```bash
rg -n -- "-O2|-O3" app/src/main/cpp/CMakeLists.txt app/src/main/cpp/cmake/GDiffuserGame.cmake app/src/main/cpp/cmake/GDiffuserDependencies.cmake
```
Expected: `fzerox_vr` and `gdiffuser_game` are `-O2`; libultraship is `-O3`.

- [ ] **Step 2: Change only the two hot targets to O3**

Change `fzerox_vr` and `gdiffuser_game` from `-O2` to `-O3`. Preserve `-fno-strict-aliasing`, `-fwrapv`, debug symbols and all existing compatibility flags.

- [ ] **Step 3: Rebuild and verify compile commands**

Run the normal Debug build, then inspect `build.ninja` for the relevant object compile flags. Expected: `-O3` appears for both targets and build succeeds.

### Task 3: Remove frame-path diagnostic overhead

**Files:**
- Modify: `app/src/main/cpp/gdiffuser_vr_host.cpp`
- Modify: `app/src/main/cpp/native_main.cpp` only if a per-frame info log exists there.

**Interfaces:**
- Consumes: current debug counters/logging.
- Produces: identical rendering/gameplay with lower Android logging and formatting overhead.

- [ ] **Step 1: Identify logs reachable every frame or every graphics task**

Inspect the log sites around `Fast3D eye`, frame perf logging, HUD probes, audio probes and VR render sections. Classify startup/error logs as retained.

- [ ] **Step 2: Disable only hot diagnostic logs/probes**

Remove or compile-gate logs/counters that execute per frame/per eye/per display list. Keep startup logs, lifecycle logs, error logs and low-frequency performance summary logging.

- [ ] **Step 3: Rebuild**

Expected: build succeeds with no functional changes.

### Task 4: Remove redundant GLES flushes

**Files:**
- Inspect/modify: `app/src/main/cpp/openxr_context.cpp`
- Inspect/modify: `app/src/main/cpp/renderer_gles.cpp`

**Interfaces:**
- Consumes: current OpenXR swapchain acquire/release flow.
- Produces: same submitted pixels with fewer explicit pipeline flushes.

- [ ] **Step 1: Audit each `glFlush()` call**

For each call, determine whether a subsequent `xrReleaseSwapchainImage`, GL fence, or frame submission already provides the required ordering.

- [ ] **Step 2: Remove only demonstrably redundant flushes**

Do not remove a flush if it protects a texture read-after-render inside the same frame (for example HUD matte compositing).

- [ ] **Step 3: Rebuild and run an OpenXR startup smoke test**

Install the APK, start NativeActivity, and verify no GL/OpenXR errors appear in logcat.

### Task 5: Device verification and measurement

**Files:** none unless a regression is found.

- [ ] **Step 1: Install optimized APK preserving app data**

Run `adb install -r` with the built debug APK.

- [ ] **Step 2: Launch and capture performance logs**

Use existing `FZeroXVR/Perf` summaries while testing a race. Confirm the app reaches 72 Hz OpenXR and note average RenderFrame ms.

- [ ] **Step 3: Regression checklist**

Verify GP start, Mute City 1 sky/background, 6DoF head rotation/translation, HUD wrist, diorama toggle, race markers, audio and quit/resume behavior.

- [ ] **Step 4: Decide whether Phase 2 is needed**

If race frame time remains above 13.89 ms or FPS materially below 72, proceed to deeper stereo/Fast3D sharing. Otherwise stop with Phase 1.
